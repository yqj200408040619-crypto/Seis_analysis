- `01_program/NDS_v2_7_1_DateGuard_H5_Verified_Patch.zip`：同版的独立补丁与安装说明，供已有原版 2.7.1 的安装目录比对或更新。补丁内三个 Python/测试文件及运行文件与完整包同名文件逐字节一致；不要对完整包重复打补丁。
- `02_full_pipeline/*Results.zip` 和 `*Validation.html`：四日六站全流程输出、日期审计、回归与相位审计及图文结果。先看 Results.zip 中的 `README_结果说明.txt`、`validation/mgs_e2e_status.json`。

## 已验证事实与边界

96 个 H5 文件通过日期审计，六台无服务端报告的下载缺段；回归测试 214 项通过、8 项跳过。全流程已完成，但 CCF 初筛的 4 段候选在前段 MUSIC 未产生可用参考：44 个频点、40,130 个窗频点中，q=0 为 33,737，q>=2 为 2,811，q=1 为 2,798；q=1 的相干度、扫描网格等失败条件大量重叠，全部方向门槛通过为 0。后段相位评估 120,927 个窗频点、150 个逐窗通过；582 组互谱复算误差最大 0。0.08–0.13 Hz 六个低频点各有逐窗通过记录，但未形成合格连续修正带。质量门槛按预期跳过真实结构反演，**无实测结构模型**。

现有仿真能恢复理想单波并大体识别独立双波，但对真实背景波场的代表性有限。单降相干度至 0.40/0.50 得到 357/299 个前段逐窗通过点；进入正式的台对、分支、投影和连续带规则后仅有 4/3 个逐频参考，修正 CCF 点与连续带均为 0；低阈值纯噪声试验出现少量误收。因此没有修改生产阈值。六点的旧版逐频边际 bootstrap 与新版同 UTC 中心、k=0 主值相位配对分析使用**不同窗口选择及相位周期处理**，是不同估计量；新版 0.09→0.10 Hz 的配对差区间跨零不能直接推翻旧版的数字，也不能支持明确升频增速。六频点完整共同窗仅 1/96，这是可重复性诊断，不应强加成生产版必须同窗的规则。

诊断问题：生产输出对 q>=2 窗将未计算的相位残差写成 0°，应标为“未评估”；改变生产代码后须更新检查点并重跑完整流程。前段 2,340 个 q=1 窗失败网格门槛，既有 12 窗网格加密测试不足以概括全部。低频频率步长 0.01 Hz 而前段为 0.005 Hz，最少连续点数 8 的设置应连同带宽及单调误差检验一起复核，不能仅靠点数放宽产出结构模型。

## 接下来建议的测试顺序

1. 对真实 q=1 的网格失败窗做覆盖全部失败型态的加密网格与门槛因子对照，跟踪方向、速度、台对引用、连续带，并加入纯噪声控制。
2. 将已知单波和独立双波注入同中心真实六站背景，按时间块划分调参段和留出段，测恢复率、误接受率与分支稳定性。
3. 对 0.08–0.13 Hz 采用一致的窗口选择、方向分支、投影和相位解缠方案，同步按时间块重采样，比较同一估计量下的速度差。保留原始点，不用平滑制造单调通过。
4. 只有留出数据支持更改时才调整正式门槛；若改代码，重新做日期、MUSIC、相位及反演入口全流程核验。
