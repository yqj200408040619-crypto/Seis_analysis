# v2.5.1 真实波形下载与 H/V Debug

本次验证使用本程序自己的 `h5data` FDSN 下载后端、H5归档、响应校正与H/V模块。没有通过外部波形下载器、Geopsy或其他波形分析软件代替程序处理。Python、ObsPy、SciPy等均为程序既有运行依赖。

## 真数据

- 服务：LMU；仪器：`BW.MGS01..HH`，三分量 HHE、HHN、HHZ。
- 请求时间：2020-11-01 00:00–02:00 UTC，原生200 Hz。
- 每分量4个半小时块，共12个H5与12个原始MiniSEED文件，完整StationXML内嵌H5并保留旁置XML。
- 归档样点4,323,686，包含MiniSEED原始记录边界的重复重叠。读取时仅合并相同样点，不插值、不重采样、不填缺测。
- 12个块的原生样点、UTC、采样率与MiniSEED一致；内嵌原始MiniSEED与StationXML校验通过。分析后源H5的SHA256均不变。
- 实际断点续传：12个块全部识别为已存在，0错误，未生成重复波形。

## 对照结果

| 频段 | 窗长 | 有效独立窗 / 总窗 | 所选候选峰 | 清晰度 | 结构状态 |
|---|---:|---:|---:|---:|---|
| 0.2–20 Hz | 120 s | 43 / 60 | 0.4240 Hz | 5/6 | incomplete_peak_shape |
| 0.1–20 Hz | 120 s | 43 / 60 | 0.4225 Hz | 5/6 | incomplete_peak_shape |
| 0.05–20 Hz | 300 s | 7 / 24 | 0.2035 Hz | 4/6 | no_reliable_peak |

每次有2个记录边缘窗因响应缓冲不足跳过，分析窗本身数据完整。120秒窗中15个窗被原波形突发噪声门限剔除；300秒窗中15个窗被同样门限剔除。未按H/V形状筛窗，未为增加有效窗而放宽门限。

约0.424 Hz为低频宽肩上的局部候选峰，没有低频侧充分下降。常规5/6清晰度允许这一项不通过，但不足以自动认定其为结构基频。扩大低频范围并加长窗后的最高评分候选峰发生变化。报告保留所有曲线、逐项评分和离散度，不输出这批数据的层厚、速度剖面或Vs30。更长窗检查同时改变了窗长与频段；同窗长对照单独检查频段影响。这些试验没有证明地下没有结构，只表明本次记录未建立可信结构解释。

## 修改

1. 新增 `hvsr-fetch`：复用原下载与核查模块，选择唯一完整三分量，检查采样率与请求历元；支持原生归档与断点续传。默认通道为`HH?`。原阵列相关命令默认仍为`HHZ`。
2. 自动层厚估计增加双侧下降条件，状态为`incomplete_peak_shape`时暂停结构。保持SESAME的3项可靠性、5/6清晰峰评分不变；额外条件属于程序的解释保护。
3. 逐窗QC分清核心窗缺测与响应缓冲不足，避免把正常边缘跳窗解释成记录内部缺测。
4. H/V CLI的`--start / --end`现在覆盖配置文件日期。
5. 界面用中文说明暂停结构的原因；补充真实数据参数比较报告与可复现脚本。

新下载命令接入时发现任务模式参数与原下载后端不一致，已改为后端正式的`window`模式，并用真实下载、模拟下载及续传核验。

## 重现

在程序目录执行；首次运行会下载相同真实记录，已存在归档可续传：

```bash
python examples/hvsr_live_test.py --directory live_hvsr
```

也可只下载三分量：

```bash
python run.py hvsr-fetch --provider LMU --network BW --station MGS01 --start 2020-11-01T00:00:00Z --end 2020-11-01T02:00:00Z --chunk-seconds 1800 --output live_hvsr/download
```

解压随附的`BW_MGS01_HVSR_Real_Test.zip`，在程序目录执行下面命令，路径指向解压后的测试根目录。此模式不进行网络请求：

```bash
python examples/hvsr_live_test.py --directory "/path/to/BW_MGS01_HVSR_Real_Test" --offline
```

GUI主窗口打开真实包的`project`目录，切换第7页即可查看/重算。相对路径配置允许移动整个真实包。
